# Privacy notice: evidence and launch decisions

The `/privacy` page is a detailed **development notice**, authored in `client/landing.ts`. It covers current account/game data, purposes, browser storage, sharing, optional future services, security, retention, requests, player age and notice changes. It uses the shared policy layout, a linked contents list, a data-category definition list, and a prominent development-status disclosure. It does not enable collection, consent, payments, privacy-request submission, export or deletion.

## User decisions

- No advertising and no sale of personal data remain the monetization commitments.
- `privacy@realms.game` is the requested **placeholder** address, not a verified working inbox. Do not add a working-contact claim or route requests to it without confirming it is monitored. Development players are directed to the administrator who enrolled them.
- Minimum intended player age is **16+**; content is unfiltered and may include mature language and references to sex, drugs, violence and alcohol. There is no age-verification system yet. Do not assume this settles every jurisdiction's teenager/child privacy requirements.
- The user supplied a planned dedicated-machine deployment: Cloudflare in front of a self-hosted game server, PostgreSQL, Valkey, workers, Caddy/Docker and admin tools, with offsite cloud backups and Workspace/Resend email. “Workspace” is interpreted as Google Workspace. These are plans, not evidence of an active deployment. Operator identity, server country, backup provider/region and provider configurations have not been supplied. “Operator” means the responsible person/entity, not an invented company name. The page clearly reserves operator identity, active contact, hosting/backup locations and retention schedule before public registration.

## Research references and limits

[FTC consumer privacy guidance](https://www.ftc.gov/business-guidance/privacy-security/consumer-privacy) emphasizes keeping disclosures consistent with actual practices. [FTC information-protection guidance](https://www.ftc.gov/business-guidance/resources/protecting-personal-information-guide-business) supports defining retention and disposal instead of inventing purge deadlines. [ICO erasure guidance](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/individual-rights/individual-rights/right-to-erasure/) illustrates that rights and exceptions need real procedures; jurisdiction is not assumed. [PayPal's privacy statement](https://www.paypal.com/us/legalhub/paypal/privacy-full) is linked for the tentative future provider's own practices. Sources were reviewed October 10, 2026; they are drafting context, not a claim of compliance certification.

Before public launch, establish responsible operator/contact details, applicable jurisdictions and processing grounds, provider contracts and geographic processing, a data/backup/log retention schedule, verified access/correction/export/deletion workflows compatible with immutable history, age-rule procedures, incident handling and any required notices/consent. The page names these gaps rather than promising functionality that is absent. No mandatory “accept policy” checkbox or blanket consent-by-browsing language is added.

## Planned dedicated-server infrastructure

The notice now names Cloudflare, Google Workspace and Resend and distinguishes their roles from the operator-managed primary server. PostgreSQL, Valkey, Caddy, Docker and workers are local software in the supplied plan, not separate external recipients merely because they are dependencies. Machine capacity and a residential address are not relevant public privacy disclosures. Offsite copies and edge/email processing mean the notice must not promise that all player data remains on the server.

Cloudflare processing applies to proxied traffic; DNS alone does not imply application-content proxying. Security cookies and traffic metrics depend on enabled features. The present server reads connection addresses directly; trusted proxy handling, log inventories, secure transport, backup encryption/access, retention and restore-aware deletion need deployment verification. Email open/click tracking is not presumed enabled or disabled. Public copy remains explicit about these pending decisions.

Provider references reviewed October 10, 2026: [Cloudflare privacy notice](https://www.cloudflare.com/privacypolicy/), [Cloudflare security cookies](https://developers.cloudflare.com/fundamentals/reference/policies-compliances/cloudflare-cookies/), [Google Workspace data processing terms](https://workspace.google.com/terms/dpa_terms.html), and [Resend privacy notice](https://resend.com/legal/privacy-policy). Provider terms inform the described data roles; they do not establish Realms configuration, locations or compliance.

The user subsequently specified Ubuntu; private-VPN SSH administration; Docker Engine/Compose; local PostgreSQL and Valkey; Cloudflare Tunnel/Caddy for game networking; Cloudflare Pages/R2 for the website/downloads; Google Workspace staff mail; Resend account emails; encrypted offsite PostgreSQL backups; GitHub Actions/container registry deployment; and separation of production, staging and personal workloads. The page reflects these privacy-relevant roles as planned controls. It does not assume R2 is also the backup destination, invent a VPN or registry vendor, or assume staging uses production player data. Before deployment, keep player records and secrets out of build artifacts/public downloads, inventory any deployment-log disclosures, and define staging data use. Deployment tooling is not described as routinely receiving player records without implementation evidence. Newsletter delivery is still unconfirmed; Resend is specifically selected for account mail.
